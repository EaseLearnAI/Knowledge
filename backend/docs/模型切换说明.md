# Memo 后端模型切换说明

## 当前配置

当前视频承接文案使用：

```env
COPYWRITER_PROVIDER=minimax
MINIMAX_API_BASE=https://api.minimaxi.com
MINIMAX_MODEL=MiniMax-M3
```

真实密钥只保存在本机 `backend/.env`，该文件已被 Git 忽略且权限为 `600`，不要把密钥写进源码、前端或提交记录。

## 更换 MiniMax 模型

MiniMax 模型名没有写死在任务、路由或数据库逻辑里。以后更换同一 OpenAI 兼容接口支持的模型，只需要：

1. 修改 `backend/.env` 中的 `MINIMAX_MODEL`；
2. 重启后端；
3. 提交一个测试视频；
4. 检查内容详情中的 `copywriting.model` 和 `copywriting.provider`。

例如：

```env
MINIMAX_MODEL=新的模型标识
```

不需要修改 `task-runner.ts`、视频路由、MongoDB Schema 或前端 API。

## 切换本地兜底文案

如果不希望调用外部模型：

```env
COPYWRITER_PROVIDER=local
```

此时使用 `LocalCopywriter`，不消耗 API 额度，但语言质量通常低于大模型。

## 接入其他模型厂商

跨厂商切换时新增一个实现 `Copywriter` 接口的 Provider，然后在 `src/app.ts` 中按配置选择。必须继续返回统一的 `CopywritingResult`：

- `oneSentenceSummary`
- `whyWorthWatching`
- `keyPoints`
- `chapters`
- `actionItems`
- `tags`
- `markdown`
- `provider`
- `model`

这样 API、任务队列、MongoDB 和客户端不需要理解每个模型厂商的原始响应格式。

## 切换后的验证

```bash
cd /Users/mac/Desktop/test/Knowledge/backend
npm run typecheck
npm test
npm run build
curl http://127.0.0.1:3110/health
curl http://127.0.0.1:3110/ready
```

模型真实可用性还需要提交一次视频任务，并确认：

```text
task.status = completed
task.progress = 100
copywriting.provider = minimax-openai-compatible
copywriting.model = 目标模型名
```
