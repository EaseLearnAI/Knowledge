# 视频解析方案评估与改进总结

## 最终采用的生产路线

采用“Node 产品服务 + 平台公开解析 + 火山云 ASR + 方舟总结”的组合：

```text
Express API
  → MongoDB 保存 SourceItem 与 ProcessingTask
  → 串行任务队列
  → B站公开 view/playurl API
  → HMAC 限时 Range 音频代理
  → 火山 volc.bigasr.auc
  → 带时间戳 Transcript
  → 豆包长稿 Map-Reduce 总结
  → 收藏详情与 SSE 日志
```

开发环境仍保留 `videosummarize` CLI 作为诊断工具，但它不是生产依赖。生产模式
强制 `VIDEO_PROCESSOR=volc_asr` 和 `COPYWRITER_PROVIDER=ark`，本地 Whisper、
Chrome Cookie 和模拟总结配置会在启动阶段被拒绝。

## 为什么这样选

本地 Python 方案可以帮助开发调试，但不满足云服务器和多用户要求。生产链路把
计算交给火山 ASR，Node 只负责解析、鉴权、限时代理、任务恢复、结果持久化和
可观察性，因此普通 CPU 云服务器即可运行。

## 已完成的关键改进

| 原能力 | 新增改进 |
|---|---|
| 本地 Whisper / CLI 同步执行 | 云 ASR + `202 Accepted` 异步任务 |
| 只在终端显示 | Mongo 日志 + 任务 SSE + Web 终端 |
| transcript 文件 | 统一 `SourceItem`、毫秒时间戳证据 |
| 无账号 | 注册、登录、JWT、刷新令牌轮换 |
| 无幂等 | 用户 + `Idempotency-Key` 唯一索引 |
| Chrome Cookie 与本地算力 | B站公开 API + 云端 ASR，不读个人电脑 |
| 只转录 | 自动生成摘要、观看价值、关键点、章节、动作、Tag、Markdown |
| 长稿单次总结易截断 | Map-Reduce + JSON 修复 + 模型降级 |
| 失败只输出文字 | 持久化错误码和原始阶段日志 |
| 无前端契约 | OpenAPI + 中文 API 文档 + TypeScript 接入示例 |

## 文案承接设计

客户端无需再拼接文案，直接读取：

- `oneSentenceSummary`：卡片和详情首屏；
- `whyWorthWatching`：解释收藏价值；
- `keyPoints`：3–7 条重点；
- `chapters`：章节与时间戳；
- `actionItems`：可以继续执行的动作；
- `tags`：列表筛选；
- `markdown`：分享、导出或富文本渲染。

生产使用方舟 `Doubao-Seed-2.0-mini`。模型额度耗尽、服务暂停或未开通时，后端会
按 `ARK_SUMMARY_FALLBACK_MODELS` 自动切换；网络故障执行指数退避；输出不完整时
再发起一次结构修复。

## 真实验证

已覆盖：

1. 4 小时 37 分 52 秒 B站公开视频无需 Cookie 成功解析；
2. 火山云 ASR 返回 75,673 字、3,102 个句级时间段；
3. ASR 任务 request ID 可在服务重启后恢复查询；
4. 5 个长稿分段与最终结构化总结全部成功；
5. HTTP 注册、鉴权、创建任务、完成任务、内容详情、删除；
6. 重复幂等键不产生第二个任务；
7. 后端 40 项自动化测试通过，iOS 9 项 UI 测试通过。

## 当前边界

- B站公开链接使用公开播放器 API，不依赖 Chrome/Cookie；小红书或抖音若触发登录
  风控，Linux 服务端只能挂载受控 Cookie 密钥文件，不能读取个人浏览器。
- 当前队列是单进程串行，符合个人开发者 MVP；多机部署时再换 Redis/BullMQ。
- 当前原视频和音频转录后默认不长期保留，只保留转录结果，符合 PRD 当前假设。

## 下一阶段建议

1. 配置云服务器域名、HTTPS、MongoDB 备份与 Secrets；
2. 把客户端 API Base URL 改成正式 HTTPS 地址；
3. B站、抖音、小红书各用 5 条公开链接做上线验收；
4. 只有平台临时 CDN 被火山拒绝时，再增加 TOS 短期对象兜底；
5. 再做搜索、Ask 和引用，不在视频 MVP 中提前加入复杂向量基础设施。
